## 3. 必须统一的定义

### 3.1 三位 mask

mask 顺序固定为 `(x^F, y^F, z^F)`，字符串如 `011`。`1` 表示该阶段在此规范坐标上有证据支持连续的、非零的语义容差；`0` 表示严格维度，或本框架下需要保守禁用的维度。

- `APP = PRE = pregrasp`：接近稳定交互构型之前的运动。
- `ENG = grasp`：进入稳定交互构型的过渡。
- `EXEC = POST = postgrasp`：保持交互构型完成搬运、放置、按压、旋转等实际任务的运动。
- `DIS = release`：退出交互构型的过渡。

对非抓取任务，用接触建立与解除解释 ENG/DIS，不能强行制造并不存在的夹爪闭合事件。EXEC 不是整个 episode。

语义 mask、框架适用性和执行门控分别存储：

`effective_mask = semantic_candidate_mask AND frame_support_mask AND task_point_support_mask`

ENG/DIS 的 `execution_gate_mask` 恒为 `000`。论文中这些过渡阶段的训练描述符分别继承相邻 APP/EXEC；本次不生成数值训练标签，也不把执行门控的 `000` 伪装成训练边界真值。

无法确认时，将交付的有效 mask 对应位保守设为 `0`，同时用 `uncertain` / `insufficient_visual_evidence` 标记。它与“已证明语义禁止”必须可区分。不得为提高开放率而猜测，也不得为了省事给所有任务统一填 `000`。

### 3.2 重力对齐坐标系

令 `zW` 为与重力反向的单位竖直方向，`c_t` 为当前标称夹爪在世界系中的**物理闭合方向**：

```text
p_t = (I - zW zW^T) c_t
h_t = ||p_t||
yF_t = p_t / h_t
zF_t = zW
xF_t = yF_t × zF_t
F_t = [xF_t, yF_t, zF_t]
E(xi) = Rz(xi_z) Ry(xi_y) Rx(xi_x)
```

这是固定顺序的外禀旋转参数化，不是相机坐标轴，也不是固定世界 X/Y，更不是可以逐项相加的欧拉角动作。

论文的 `R_nom e_y` 建立在工具局部 Y 是闭合方向的约定下。LIBERO/robosuite 的 EEF、夹爪根节点、手指节点可能有固定旋转。必须检查当前机器人模型并建立固定工具坐标变换，使论文中的工具 Y 对应真实闭合轴，不能直接拿 `eef` 旋转矩阵第二列代入。用至少一个左右指位置/滑动轴实例验证，并在 `coordinate_calibration.json` 记录：

- EEF/控制点的定义与位置；论文工具系到数据工具系的固定旋转。
- 四元数顺序、旋转表达、闭合方向符号与手指开口度计算方法。
- 标称参考如何得到；实际观测姿态若只是其近似，明确写出，不能悄悄替代动作积分标称参考。
- 数据中的手指关节可能一正一负，开口度不能照搬另一项目的两个 qpos 直接求和。

当 `h_t < 1e-6` 时，按论文使用退化保护，禁用额外释放，不得为了产生 mask 随意换一个水平轴。单独记录退化区间与 `runtime_guard_mask=000`；一次短暂退化不等于该任务全部语义轴永远为零。

### 3.3 语义自由度与证据

- 观察到示范沿某轴旋转，不代表该轴可容差；该旋转可能恰好是必须严格完成的动作。
- 未观察到旋转，也不意味着无容差。
- 圆柱/球的连续对称性与方体 90°/180° 的离散对称性不同；离散等价抓取不能直接支持其间连续旋转。
- mask=1 不代表任意角度或默认正负 30° 都有效。LIBERO 的数值幅度留待后续验证，`directional_bounds_rad` 保持 `null`。
- 一条示范支持的是该任务下一个具体抓取/执行模式的候选标注，不足以证明所有示范模式都共享同一 mask。
- 不能因为优化器更容易求解、关节速度更低而把语义不允许的轴改为 1。

必须在参考说明中保留以下对照：

2. **自由放置 vs 不倾斜**：同物体、同目的地也会因语言条件改变 EXEC。直立圆柱 111→001；横圆柱 111→101；方体 111→001。不能从一条看起来很平稳的示范自动补出“不倾斜”要求。
3. **不倾斜 vs 目标对齐**：横圆柱 101→100，方体 001→000；目标平面内朝向多锁了 z。
4. **圆钮 vs 横杆**：盖回的 EXEC 相同，APP 由抓取部位而不同；抓杯把与抓杯身也必须分别识别。
5. **同一物体不同子目标**：开盖放桌与盖回锅口不能共享 EXEC。这条原则要用于 LIBERO 的全部长任务。

## 5. 枚举 40 个任务并选择代表性示范

范围严格为 `libero_spatial`、`libero_object`、`libero_goal`、`libero_10` 各 10 个任务。使用本地 benchmark 的任务顺序/ID 和处理记录交叉核对，输出完整 manifest，不能把 libero_90 算进来，也不能因名称相似合并不同任务。

每个任务只选一个主要代表性 episode，按以下固定规则：

1. 从完整且成功保存的 demo 中选择，不把失效回放作为代表。
2. 按保留帧数与本任务成功 demo 帧数中位数的距离排序，同分按原始 `demo_N` 数字升序。
3. 按统一提取规则检查候选的主视角关键帧是否覆盖完整语义、关键接触是否可见。默认取首个合格候选；若遮挡或缺失严重，可以检查后续候选的同类主视角帧，记录替换原因。不能按“更容易得到预期 mask”挑选。
4. 候选筛查不得使用待预测 mask。记录所有被查看候选、选择次序和理由。
5. 若发现不同抓取模式，只为主示范的模式给出本轮标签，并报告 `multiple_modes_observed`。不能用一次代表视频宣称覆盖该任务的所有模式。

manifest 至少记录 suite、task_id、task_name、原始 language、源 HDF5、处理后 HDF5、demo_id、帧数、source_step_indices、选择依据及输入指纹。原始 demo_id 保留，不能按成功 demo 的排序重编号。

## 6. 生成视频与事件关键帧

从已处理 HDF5 的 `obs/agentview_rgb` 导出主视角视频，不必为看视频重新执行物理仿真。逐帧流式读取，避免一次把 40 个任务图像装入内存。

按处理脚本约定校正一次图像方向；当前数据是 raw LIBERO 图像，查看时通常需要 180° 旋转。用可见桌面/机械臂检验方向，不重复旋转。视频与截图都保留处理后帧号、原始帧号和物理时间标记。

核实真实控制频率，不能照搬 MuJoCo 项目的 10 Hz。当前再生成脚本使用 LIBERO 的 20 Hz：压缩后重放时间按保留动作计，原始 `source_step_indices` 中的空洞代表被过滤动作，不应变成重放中的停顿。分别记录 `processed_frame`、`source_frame`、`replay_time_s`；注明十个 settling 动作和时间零点约定。

观测在 action 之前记录。`obs[t]` 与 `action[t]` 是执行前状态及下一动作，不能把 `action[t]` 的效果解释为已经出现在 `obs[t]`。旧兼容字段 `states[0]` 早于 settling；与图像对齐时使用 `tasktol/pre_action_states` 等实际记录。末帧不一定含最后动作完成后的画面；缺失终态截图就明确缺失，不能把 pre-action 末帧当作 post-action 成功证据。

### 6.1 阶段识别

结合原始夹爪命令和两个手指的真实开口变化生成事件候选，再由主视角关键帧判断其语义：

- APP：进入目标稳定交互之前的接近。
- ENG：接触建立/闭合过渡开始，到稳定握持/稳定交互构型建立。
- EXEC：稳定构型下实际执行，直到解除接触/释放开始。
- DIS：解除接触/打开过程，直到退出交互；随后若有下一子任务，再进入其 APP。

夹爪命令符号应从当前原始控制接口校验，不能套用训练导出后可能被反转的符号。稳定确认规则保持统一：核实论文“三个连续 10-Hz 观测”在代码中是按稳定判定次数还是采样跨度计数，再按本数据时间戳实现等效持续时间。三个采样点的首尾跨度为 0.2 s，三个控制周期则为 0.3 s，不能混淆；记录采用的定义和帧数，也不直接把 20 Hz 的三帧冒充原来的确认窗口。

把手拉动、按钮按压、推物等不一定有明显夹爪开闭。事件提取器若没有发现可用变化，输出 `no_gripper_transition`，按统一规则补充起点、终点和等时间间隔的主视角帧，再由这些图像判断接触/操作阶段。不能伪称这些辅助帧由夹爪事件触发，也不能调用任务专属成功谓词补分段。

夹爪抖动、误闭合、重抓属于操作事件，不一定都是新的语义子任务。打开抽屉、取物、放物、关门等实际发生的前置/后续操作也应进入有序子任务表；从关键帧无法分清的顺序或边界标记为不确定，不强行给精确时刻。

### 6.2 每个子任务的截图集合

所有任务使用同一套事件定义，仅保存主视角：

| 关键帧 | 选取原则 | 主要用途 |
|---|---|---|
| `episode_initial` | episode 第一幅有效观测，注明是否已 settling | 整体摆放、目标与语言对应 |
| `subtask_start` | 当前子任务 APP 起点 | 子任务对象与起始状态 |
| `pre_engagement` | ENG 开始前最后一幅稳定图像 | 局部接触几何、APP mask |
| `engagement_complete` | 稳定握持/接触首次确认 | 实际抓取部位、工具与物体关系 |
| `execution_mid` | 由相邻夹爪事件确定的 EXEC 候选区间中点；辅助帧采用预设时间网格 | 持续语义是否成立 |
| `pre_disengagement` | DIS 开始前最后一幅有效图像 | 目标对齐与释放前要求、EXEC mask |
| `disengagement_complete` | 脱离完成后第一幅确认图像（若有） | 结果与下一子任务衔接 |
| `episode_final_available` | 最后可用观测，注明 pre/post-action 属性 | 轨迹末段核对 |

给每个夹爪过渡候选保留前后约 0.3 s 的主视角连续帧。主抓取/释放截图以事件前最后一帧为基准，同时保留稳定确认帧；不要移动事件时间来迁就更好看的截图。若被遮挡，按统一顺序扩展为前后 0.6 s，仍不清楚则记录未知。没有的事件标记 `not_applicable` 或 `not_observed`，不要伪造截图。无事件或事件间距很大时，统一补充区间等时间采样（默认含端点共 8 帧）；将规则及参数写入 manifest，并对全部任务一致应用。

实际打开并查看每个任务的带帧号主视角关键帧与 contact sheet。先查看统一规则提取的图像包，必要时按同样的规则扩展事件邻帧。不能仅运行导出命令、读取文件名，就声称已完成视觉判断。

## 7. 每个子任务的逐轴判定流程

### APP：看“哪里、怎么接触”

先识别接触部位是物体主体、瓶颈、杯把、盖钮、横杆、棱边还是机构表面，再判断局部形状及其相对 F 的方向。局部接触几何优先于整个物体的名称或大轮廓。

对 x/y/z 每一轴分别写一句可核查的判定依据，关联截图 ID：

1. 该轴旋转是否保持允许的局部接触/接近关系？
2. 若使用基础 y 释放，真实闭合轴与其水平投影是否足够一致，控制点是否对应所假设的接触中心？
3. 若使用额外轴对称性，对称轴实际是否沿该规范轴？有无把手、嘴、棱边、非圆截面破坏该局部等价性？
4. 这是一段连续局部容差，还是仅几个离散姿态等价？后者不能直接置 1。

### EXEC：看“物体、操作、目标共同允许什么”

按论文写出：

`semantic_candidate_mask = object_mask AND operation_mask AND goal_mask`

分别判断：

- **物体属性**：是否需要直立、保存液体、保持某个支撑面等。看不到液体、指令也没要求时，不凭“杯子”一词虚构有液体。
- **操作语义**：自由放置、不倾斜、扶正、对齐、旋转到指定角、按压、推拉、开/关等。区分要求与示范恰好采取的动作。
- **目标条件**：宽松托盘、匹配区域、狭窄开口、抽屉内部、架子、锅口、支撑关系及必要间隙。
- **阶段含义**：要求只在终点成立，还是整个 EXEC 持续成立？记录 `terminal_defined` / `stage_persistent` / `both` 及依据；按论文用终端兼容的阶段描述符贯穿整个阶段，不能为了中途自由度临时开放终点必须锁定的轴。

APP 与 EXEC 独立判定；EXEC 不是把 APP 原封不动复制过来，也不是默认与 APP 做交集。物体完成抓取后与夹爪共同转动，其容差由当前操作目标重新决定。

### 框架适用性：按维度保守置零

1. **非重力参考**：若某个可释放方向必须依赖未知机构轴、倾斜表面法向、工具系或任意物体系，而现有 F 无法表达，相关维度置 0，理由为 `unsupported_reference_axis`。机构存在不等于三轴全部不适用；逐轴保留可由重力和当前抓取几何确立的自由度。不得额外旋转一个任意任务坐标系来救回该轴。
2. **任务点偏置**：先确认真正需要保持的位置/接触点，不把物体 COM 一概当成严格任务点。设控制点到关键任务点的世界向量为 r，绕控制点施加 D 会产生 `delta_p = (D - I) r`。若相关旋转改变了必须保持的接触点、插入点、支撑位置且无法由允许语义吸收，该轴置 0，理由为 `task_point_offset`。r 平行于该轴时可能不发生该方向的点位移，不能因存在偏置就一律三轴清零。标注阶段只做有视觉依据的定性判断；缺少尺度就记录未知，不编造厘米级数值。
3. **阶段内轴映射不成立**：瞬时 F 随标称姿态变化，需结合阶段起止及辅助帧判断，不能只凭一个终点截图。有限关键帧并不证明所有中间时刻都成立。若一个二值阶段掩码不能在整段保持相同语义，记录 `phase_axis_inconsistency` 并保守禁用相关轴。孤立退化按运行时保护记录，不能偷换成任意轴投影。
4. **连续盒表达不足**：若某自由度必须多个角度耦合、围绕移动支点运动或依赖恢复动作，不能把单轴局部导数为零当作固定可分离 RPY 盒的充分依据。无法支持的相关维度置 0，理由为 `coupled_constraint`。
5. **证据不足**：目标/接触遮挡或方向不确定，补看邻帧仍不能确认的轴置 0，理由为 `insufficient_visual_evidence`，置信度不得伪装为高。

同时报告候选语义 mask 与最终有效 mask，使“任务语义严格”“框架不支持”“信息不足”三个来源可区分。不要先假设全部 1，再把能想到的风险随意相乘；每一项 1 和每一项被清零的维度都要有具体依据。
