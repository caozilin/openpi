# 2026-11-04 推理请求耗时轻量调查

本次仅分析既有记录、读取服务日志/状态并进行约3.94MB传输测试。未加载模型、未启动推理或评测、未修改已冻结源码和结果。临时诊断SSH连接结束后关闭。

## 结论

当前上传链路是明确瓶颈，也是本次变慢的主要嫌疑：传输测试完全不执行模型，同一SSH控制连接并发发送六份393520字节的随机数据耗时5.20秒，总吞吐3.63Mbps。五份请求约5.18–5.20秒，一份2.21秒。单份上传0.75–2.23秒，单份下载0.26秒；SSH空命令往返0.10–0.19秒，ICMP约82–450ms。当前测量发生在评测结束后，不能精确还原评测期间网络与GPU耗时的占比。

真实评测每次请求含两张256×256 RGB原始图像，MessagePack包约393520字节；WebSocket显式compression=None，SSH命令未启用压缩。本地100次序列化平均0.0226ms，可以排除打包造成秒级延迟。六个逻辑端口共用一个SSH连接，因而共享该连接可用吞吐；不将共享连接本身断言为唯一原因。

## 尚缺的测量

WebSocket服务原本返回server_timing.infer_ms，但本次客户端仅累计端到端inference_wall_seconds，未保存返回的服务端计时；服务器日志也无逐请求耗时。因此无法事后准确拆分GPU计算/网络传输，不能断言GPU速度完全没变化。当前GPU快照无运行中的本次推理任务，也不能用于证明历史GPU计算速度。

下一次运行可在不改变策略输入输出和控制参数的前提下，逐请求保存端到端时间、server_timing.infer_ms与包大小；在模型未加载时先做同大小六路上传预检。若需优化，优先评估无损图像压缩或传输路径，避免为提速改变图像像素或模型输入。

证据：transport.json、historical_breakdown.json；check_transport.py是有界传输检查，不包含模型/评测逻辑。
