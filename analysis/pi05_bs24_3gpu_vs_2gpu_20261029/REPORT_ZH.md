# 固定全局 batch24：6卡、3卡、2卡训练短跑对比

2026-10-29，Asia/Shanghai。3卡和2卡实验已完成、GPU已释放；6卡数据来自此前已结束的短跑。

结论：相同全局batch、模型、数据、初始化和按更新步数定义的学习率下，三组早期训练loss基本重合。增加卡数提高总吞吐，但收益小于卡数增加比例；2卡每GPU的资源效率最高。此轮2卡跨NUMA，速度不能解释为单纯卡数效应。

## 实验设置

- 全局batch固定24：6×4、3×8、2×12。
- π0.5官方32维接口，gemma_2b_lora / gemma_300m_lora；state开启，max_token_len200，action_horizon16，仅前7维动作loss。
- 同一数据集 `caozilin/franka_100_nominal`；同一份 state7/actions7 统计，SHA-256为 `e1e3c4e7630f6ee524d99ae99cb0dfe8f61306d83c3feebbfa564edc0c5b7a07`。
- 从官方pi05_base重新初始化，不从上一短跑恢复。所有优化器、数据、loss和学习率设置保持一致；配置仅name不同，全局batch同为24，使用官方数据并行路径fsdp_devices=1。
- warmup1000到5e-5，余弦衰减到总第15000步的5e-6；save_interval=keep_period=1500，log_interval10。短跑未到1500步，因此不生成模型checkpoint。
- 新配置：`pi05_franka_mujoco_state_action7_lora_bs24_3gpu`、`pi05_franka_mujoco_state_action7_lora_bs24_2gpu`。
- 3卡使用GPU0–2；2卡使用GPU3–4；两个进程几乎同时启动。计时器等待第一个实际训练进度点，跳过空进度行和首步编译。约900秒后在下一个10步记录点发送SIGINT，退出码-2为计划停止。

## GPU拓扑与并发条件

- GPU0、1、2位于NUMA0，GPU0/1为PIX，其余组内连接为NODE。
- GPU3位于NUMA0，GPU4位于NUMA1，二者连接为SYS，通信跨CPU/NUMA节点。
- 因此本次2卡布置不代表该服务器上所有2卡组合的最好速度。要隔离卡数影响，还需在同NUMA/同PCIe交换机的2卡组合单独复测；本次未扩展实验。
- 3卡与2卡同时运行，共享CPU、内存、磁盘及部分PCIe资源。重叠时段1分钟load average约14.84–22.24；6卡参考是此前单独运行，因此不是严格同环境的纯GPU扩展性基准。
- 资源采样的GPU利用率中位数两组都是100%；这不能区分计算、显存访问和通信瓶颈。没有profile证据支持给通信耗时或最慢卡等待时间填写精确百分比。
- 全局batch固定而卡数增加后，单卡计算量降低，但完整参数复制、梯度同步和固定开销不会按相同比例减少，可以解释扩展收益小于理想值的可能机制；本轮不把它当作已精确定位的唯一原因。
